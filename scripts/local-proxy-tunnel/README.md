# Rutube Local Proxy Tunnel

Этот туннель предназначен для проксирования запросов от вашего локального фронтенда (или бэкенда) к защищенным API (например, Rutube) с целью обхода строгих браузерных ограничений **CORS** и маскировки заголовков `Origin`/`Referer`. 

Инфраструктура разворачивается локально через **Docker Compose**, используя связку **Tinyproxy** (для маршрутизации) и **Ngrok** (для создания стабильного внешнего https-адреса).

## 📋 Системные требования
- ОС: Linux (Ubuntu/Mint/Debian и др.)
- Установленные `docker` и плагин `docker compose` (или `docker-compose`)

---

## 🚀 Как использовать

Скрипт управления `start-proxy.sh` поддерживает как удобное интерактивное меню, так и быстрые CLI-флаги.

### 1. Интерактивный режим
Запустите скрипт без аргументов:
```bash
./start-proxy.sh
```
Перед вами появится меню, где с помощью цифр вы можете легко запустить туннель, выключить его, обновить токен или посмотреть статус контейнеров.

### 2. Быстрый запуск (CLI-флаги)
Для автоматизации разработки вы можете использовать прямые команды:
- `./start-proxy.sh --start` (или `-s`) — Полный запуск туннеля. Скрипт сам поднимет Docker, подождет коннекта и выдаст вам готовый `https://...` URL.
- `./start-proxy.sh --stop` — Остановка и удаление контейнеров туннеля.
- `./start-proxy.sh --status` — Проверить, крутятся ли сейчас контейнеры.
- `./start-proxy.sh --url` — Повторно вывести на экран ваш активный URL-адрес от Ngrok.
- `./start-proxy.sh --logs` — Вывести "живые" логи контейнеров.

## ⚙️ Настройка токена

При первом запуске скрипт автоматически попросит вас ввести `NGROK_AUTHTOKEN`.
1. Зарегистрируйтесь на сайте и перейдите в [Ngrok Dashboard: Your Authtoken](https://dashboard.ngrok.com/get-started/your-authtoken).
2. Скопируйте свой токен (вида `3F3z...`).
3. Вставьте его в терминал.

Скрипт сохранит этот токен в локальный файл `.env` (который не нужно коммитить) и настроит переменные для Docker Compose. **Если токен скомпрометирован или его нужно заменить**, используйте Пункт 6 в интерактивном меню скрипта.

## 🛠 Частые проблемы и Troubleshooting

### Ошибка `ERR_NGROK_334` (The endpoint is already online)
Ngrok закрепляет за бесплатными аккаунтами 1 статический домен. Если вы перезагружали компьютер или контейнер упал, на серверах Ngrok может "зависнуть" ваша старая сессия. Из-за этого новый запуск блокируется.
**Решение:**
1. Остановите контейнеры: `./start-proxy.sh --stop`
2. Откройте [Ngrok Dashboard -> Tunnels -> Agents](https://dashboard.ngrok.com/tunnels/agents).
3. Найдите активного Агента и принудительно нажмите кнопку **Stop Agent**.
4. Запустите туннель заново.

### Ошибка `ERR_NGROK_105` (Authentication failed)
Ваш токен введен с ошибкой, скопирован не полностью или был отозван через дашборд.
**Решение:** Сгенерируйте новый токен в панели Ngrok и обновите его в скрипте через Пункт 6 интерактивного меню.

### Туннель запущен, но запросы падают с таймаутом
Вероятно, проблема на стороне `Tinyproxy`. Проверьте логи через `./start-proxy.sh --logs`. Если вы видите слишком много ошибок или блокировок, перезапустите туннель.

## 🔌 Интеграция с кодовой базой
После успешного старта `start-proxy.sh` выдаст вам ссылку. Скопируйте этот `PROXY_URL` и вставьте его в `.env` конфигурацию вашего бэкенд-сервера (например, `kino-club/.env`):
```env
PROXY_URL=https://washroom-calamity-clapper.ngrok-free.dev
```
После этого перезапустите ваш рабочий проект. Теперь он будет слать все "проблемные" запросы (например, к Рутубу) прозрачно через этот туннель!
