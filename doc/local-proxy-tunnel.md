# Local Proxy Tunnel (VPN Bypass)

Этот модуль позволяет обходить системный VPN для выборочных сайтов (например, Rutube, Кинопоиск, Okko), пуская трафик через локальную сеть провайдера. 

Система работает на базе **Docker** и технологии **ipvlan**, которая позволяет контейнерам получать отдельный MAC-адрес и IP-адрес в локальной сети, игнорируя системные маршруты хоста (включая VPN, например ZeroTier или WireGuard, которые заворачивают весь трафик через себя).

## Архитектура

В директории `scripts/local-proxy-tunnel/` находятся:
* `docker-compose.yml` — конфигурация контейнеров
* `Dockerfile.socks5` — инструкция по сборке локального SOCKS5 прокси (основан на `serjs/go-socks5-proxy` и `alpine`)
* `nginx.conf` — конфигурация Nginx для Reverse Proxy

В docker-compose настроены 2 сети:
1. `default` — стандартная сеть Docker для доступа с хоста (прослушивание `127.0.0.1:1080` и `127.0.0.1:8888`).
2. `physical_net` — сеть типа `ipvlan` (L2), подключенная к физическому Wi-Fi адаптеру хоста (`wlp44s0`), с диапазоном адресов `192.168.1.0/24` и шлюзом провайдера `192.168.1.1`.

### Компоненты

1. **ruzone_proxy (SOCKS5)**
   Выступает в роли Forward Proxy. Принимает соединения на `127.0.0.1:1080`.
   Внутри контейнера прописано правило маршрутизации, которое удаляет шлюз Docker по умолчанию и направляет трафик жестко через шлюз провайдера (`192.168.1.1` через интерфейс `eth1`, подключенный к `physical_net`).
   
2. **rutube_proxy (Nginx)**
   Выступает в роли Reverse Proxy на `127.0.0.1:8888`. Используется для прямых запросов к видеопотокам, может подменять заголовки (Origin, Referer, User-Agent) и перенаправлять видео напрямую на `rutube.ru`. Также использует сеть `physical_net` для обхода VPN.

3. **rutube_ngrok**
   Туннелирует `rutube_proxy` во внешнюю сеть через Ngrok (если требуется внешний доступ к видеопотокам).

## Использование с браузером (SwitchyOmega)

Чтобы смотреть Rutube в браузере, обходя VPN, необходимо настроить расширение **SwitchyOmega** на использование SOCKS5-прокси из этого туннеля:

1. Откройте настройки SwitchyOmega.
2. В разделе **Profiles** создайте или выберите профиль типа **Proxy Profile** (например, `ruzone_proxy`).
3. Заполните данные:
   * **Protocol**: `SOCKS5`
   * **Server**: `127.0.0.1`
   * **Port**: `1080`
4. В левом меню выберите профиль **auto switch**.
5. Добавьте правила (Switch rules):
   * `Condition Type`: `Host wildcard`
   * `Condition Details`: `*.rutube.ru`
   * `Profile`: `ruzone_proxy`
   *(Сделайте то же самое для `*.kinopoisk.ru`, `*.okko.tv`, `*.yandex.ru` и т.д.)*
6. Убедитесь, что **Default** внизу установлен в **[Direct]**.
7. **ВНИМАНИЕ**: В списке **Bypass List** профиля `ruzone_proxy` **не должно быть** `rutube.ru` или `*.*.ru`. Иначе трафик пойдет "напрямую", а в вашем случае напрямую — это через системный VPN.
8. Сохраните настройки (Apply changes) и выберите `auto switch` в меню расширения.

## Запуск

Перейдите в директорию и поднимите контейнеры:
```bash
cd ~/Dev/ubuntuInstaller/scripts/local-proxy-tunnel
docker compose up -d --build
```
